## 2\. 計測仕様

| 項目                                                                    | 内容                                                                    |
| --------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 計測項目                                                                  | 温度（℃）、湿度（%RH）※CO2は廃止                                                  |
| センサー                                                                  | SHT40I使用 高精度デジタル温湿度センサーモジュールキット（秋月電子 130207 / AE-SHT40I-AD1F-R2-SIP4） |
| 接続方式                                                                  | I2C（電源電圧2.3V〜5.5V対応、XIAO ESP32C3の3.3Vラインに直結可）                         |
| 計測間隔                                                                  | 10分                                                                   |
| 開発環境                                                                  | Arduino framework（PlatformIO + VSCode）                                |
| 通信方式                                                                  | WiFi経由でHTTPS POST                                                     |
| デバイス識別                                                                | 複数デバイス拡張前提のため、デバイスごとに固有ID・APIキーを発行                                    |
| 電源                                                                    | 常時給電（詳細は4章）                                                           |

**センサー変更に伴う補足**

- SHT40Iは5V耐圧のため、レベル変換回路なしでの直結が可能（DHT20からの置き換えでも配線構成はほぼ変わらない）。

- CO2センサー廃止に伴い、メイン要件定義書側の以下の項目も併せて更新が必要（本ファイルの範囲外）:

    - APIエンドポイントのバリデーション対象からCO2を除外

    - `measurements`テーブルの`co2`カラム削除

    - 異常値アラート閾値表からCO2関連行を削除

    - 全体構成図・スコープ外記載の見直し

## 3\. 自己発熱対策

ESP32C3はWiFi通信時に発熱し、近接するSHT40Iの計測値（特に温度・湿度）に誤差を与えやすい。以下を設計指針とする。

- センサー基板をESP32本体から**物理的に離す**（数cm〜10cm程度、配線を延長して設置）

- ケース設計時に**通気孔を確保**し、熱がこもらない構造にする

- WiFi送信直後は基板温度が上がりやすいため、**計測→送信の順で、送信前に計測を完了させる**

- 消費電力の大きいWiFi送信は毎回ではなく計測後にまとめて行い、アイドル時間を確保する

※CO2センサー廃止によりSCD40のウォームアップ時間確保に関する項目は不要になった。

## 4\. 電源設計（新規検討・決定）

### 4\.1 検討: DCジャック化 vs Type-C据え置き

| 観点                                           | Type-C（現行）                                   | DCジャック化                                      |
| -------------------------------------------- | -------------------------------------------- | -------------------------------------------- |
| 部品点数                                         | 追加部品不要                                       | DCジャック＋逆流防止ダイオードが必要（XIAO ESP32C3の5Vパッドへ直接配線） |
| コネクタ耐久性                                      | 常設・抜き差し少なければ問題なし                             | 抜き差し頻度が高い/振動がある用途で有利だが、今回は据え置き設置のため恩恵は小さい    |
| ケース設計                                        | Type-C用の切り欠きのみで済む                            | ジャック用の穴あけ・固定が別途必要                            |
| 設計思想との整合                                     | 要件定義書全体の「個人利用・少数台数はシンプルさ優先」の方針と合致            | 将来的な量産化・複数台展開時に配線の取り回しをより堅牢にしたい場合は検討価値あり     |

**決定: 当面はType-C給電を継続**。常時設置・抜き差しがほぼ発生しない用途のため、DCジャック化によるメリットが小さく、追加部品（ダイオード等）や筐体加工の手間に見合わない。将来的に振動のある場所への設置や複数台の量産設計を行う段階で、5Vパッド＋ダイオード＋DCジャック構成への変更を再検討する。

### 4\.2 Type-C電源仕様

| 項目                                                                                                                   | 値                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 入力電圧                                                                                                                 | 5V                                                                                                                   |
| 推奨電流                                                                                                                 | **最低1A、余裕を見て2A品を推奨**                                                                                                 |
| 補足                                                                                                                   | オンボードレギュレータで3.3Vへ降圧（3.3Vラインの出力上限は約700mA）。WiFi送信時のピーク電流は300〜400mA程度出ることがあるため、安価なアダプタで定格割れしやすい1Aちょうどより2A品の方が安全マージンが大きい |
| 電源形態                                                                                                                 | 常時給電（USB-C ACアダプタ or 汎用USB-C電源）                                                                                      |

## 5\. ハードウェア試作・量産・筐体計画

| フェーズ                                                | 内容                                                  |
| --------------------------------------------------- | --------------------------------------------------- |
| 試作（1台目）                                             | ユニバーサル基板で製作。自己発熱対策（3章）を踏まえた配線引き回しをここで検証する           |
| 量産検討（複数台化）                                          | 台数を増やすタイミングでプリント基板（PCB）を設計し、発注する（KiCad等を想定、詳細設計は別途） |
| 筐体                                                  | 3Dプリンタは未所持のため、設計データ（Fusion 360等）を作成しFabLabで出力する     |

- ユニバーサル基板での試作段階では、センサー配置・配線長を含めた自己発熱対策の実地検証を優先する。ここで得た知見をPCB設計・筐体設計にフィードバックする。

- 筐体設計時は、通気孔（3章参照）を確実に確保できる形状にする。DCジャック化を将来採用する場合はジャック用開口も併せて検討する。

## 6\. データモデル（デバイス関連部分・更新版）

```sql
CREATE TABLE devices (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name         TEXT NOT NULL,           -- 例: "自室", "リビング"
  api_key_hash TEXT NOT NULL,           -- APIキーはハッシュ化して保存
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE measurements (
  id           BIGSERIAL PRIMARY KEY,
  device_id    UUID NOT NULL REFERENCES devices(id),
  temperature  NUMERIC(4,1) NOT NULL,   -- ℃
  humidity     NUMERIC(4,1) NOT NULL,   -- %RH
  -- co2 カラムは廃止（CO2センサー廃止のため）
  measured_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_measurements_device_time ON measurements (device_id, measured_at DESC);
```
